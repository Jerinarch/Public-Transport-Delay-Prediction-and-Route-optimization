1. Executive Summary

This document presents a rigorous, line-by-line comparative analysis between two distinct bodies of work in the domain of urban public transport delay prediction:

📄 Document A: Main Reference Paper
  • Title: "Scalable Transit Delay Prediction at City Scale"
  • Authors: Boudabbous, Karaa, Sboui, Montecinos, & Alam (ÉTS Montréal & Trent University)
  • Focus: Pure ML research — systematic feature engineering, dimensionality reduction, and deep learning model comparison
  • Dataset: 6 months of STM Montréal bus data (196 routes, ~5.5M elementary segment observations)
  • Key Result: LSTM achieves R² = 0.6621, trip-level RMSE = 1.85 min
📐 Document B: Project Architecture
  • Title: "Intelligent Public Transport Delay Prediction & Route Optimization System Using ML"
  • Scope: BMTC Bengaluru (6,000+ active buses)
  • Focus: End-to-end production system design — hybrid polyglot data architecture, real-time streaming, route optimization
  • Architecture: Lambda/Kappa hybrid (Kafka + Redis + PostGIS + OSRM + ClickHouse)
  • Key Innovation: Dual-interface (commuter app + agency dashboard) with zero-cost open-source stack
⚡ Key Finding

The two documents are complementary, not competing. The reference paper provides the algorithmic and model-level depth (what to predict and how to engineer features), while the project architecture provides the system-level infrastructure (how to deploy, scale, and serve predictions in real-time). Together, they form a complete end-to-end intelligent transit system.

5.2 Feature Engineering Approach

📄 Reference Paper: Automated Aggregation Framework
  • Total Features: 1,683 per elementary segment
  • Method: Systematic exploration of 23 aggregation combinations: spatial (H3 res 9, res 10, route, segment) × temporal (hour of day, time-of-day periods, 96 per-hour boolean intervals) × route-based groupings
  • Statistics: 9 per combination (mean, std, min, max, Q25, Q50, Q75, count, sum)
  • Target Variable: Elementary-segment pace (seconds/meter) — normalized for segment length
  • Dimensionality Reduction: Adaptive PCA → 83 components (95% variance)
  • Innovation: Fully automated, reproducible, and transferable to other networks
📐 Project: Domain-Driven Manual Engineering
  • Total Features: 35 (13 direct + 22 derived)
  • Method: Domain-expert curated features from 13 source files covering weather, traffic, road geometry, schedules, and disruptions
  • Derived Features: delay_minutes, congestion_index, service_reliability_score, occupancy_ratio, travel_time_ratio, etc.
  • Target Variable: delay_minutes (direct delay in minutes)
  • Schema: Star Schema (Kimball) with pre-aggregated fact table
  • Innovation: Multi-domain fusion (weather + traffic + disruptions in single pipeline)
⚠️ Critical Insight: Complementary Approaches

The reference paper's 1,683-feature automated aggregation is statistically exhaustive but domain-agnostic — it captures every possible spatiotemporal statistic without domain knowledge about traffic, disruptions, or road characteristics. The project's 35-feature set is domain-rich but manually curated — each feature has a clear physical interpretation and engineering rationale.

Recommendation: Adopt the reference paper's systematic aggregation framework ON TOP OF the project's domain-rich feature set to create a hybrid feature engineering pipeline that combines statistical exhaustiveness with domain knowledge.

6.2 Key Model Finding from the Reference Paper

🏆 Simpler Recurrent Architectures Outperform Transformers

The LSTM with only 31,000 parameters outperformed all transformer models (PatchTST: 2.4M params, Autoformer: 1.9M params) by 18–52%. This challenges the assumption that architectural sophistication correlates with performance. Stop-to-stop delay patterns exhibit short-term temporal dependencies better captured by recurrent gates than attention mechanisms. Transformers overfit on the 6-month dataset.

  • LSTM: 26 min training, 300ms inference, 2.1 GB GPU memory
  • XGBoost: 1.5 min training, 100ms inference, CPU-only — compelling practical alternative
  • PatchTST: 35 min training, 800ms inference, 4.3 GB — worse accuracy, higher cost

11. Models to Implement from the Reference Paper

Based on the reference paper's rigorous comparative evaluation, the following models and techniques should be implemented in the project, ranked by priority:

11.1 Priority 1: Must Implement

🏆 1. LSTM with Bidirectional Encoder-Attention-Decoder

Why: Best-performing model (R² = 0.6621) with remarkably few parameters (31K). Outperforms all transformers by 18–52%. Perfect for the project's compressed feature space.

Architecture: 3 bidirectional LSTM layers (32 units each) + Bahdanau attention + dropout (0.383) + temporal smoothness penalty (λ = 0.01). Training: Adam optimizer with learning rate scheduling (lr = 1.54×10⁻³), batch size 16, gradient clipping (clipnorm = 2.01).

Integration Point: Train on project's fact_integrated_bus_operations features → serve via FastAPI /api/v1/eta/predict.

🔧 2. Systematic Multi-Resolution Feature Engineering Framework

Why: The reference paper's 1,683-feature automated aggregation captures spatiotemporal patterns that manual 35-feature engineering cannot. The paper explicitly demonstrates that feature engineering quality drives model performance more than model architecture complexity.

How: Apply the 23-aggregation-combination framework to the project's richer data sources (adding traffic, disruption, and occupancy domains to the H3-based aggregation).

11.2 Priority 2: Strongly Recommended

📉 3. Adaptive PCA Dimensionality Reduction

Why: If the systematic feature engineering generates 1,683+ features, Adaptive PCA compresses them to ~83 components (95% variance) — making model training computationally feasible while preserving information.

Implementation: sklearn.decomposition.PCA(n_components=0.95) with walk-forward fitting to prevent temporal leakage.

📊 4. Walk-Forward Temporal Cross-Validation

Why: Standard k-fold CV leaks future information. Walk-forward validation with temporal gaps provides realistic deployment-like performance estimates.

Implementation: 5 sequential folds with 15-minute temporal gaps. Train on expanding window, validate on next month, test on month after.

11.3 Priority 3: Valuable Additions

📐 5. Hybrid H3+Topology Spatial Clustering

Why: Useful for organizing BMTC's 2,000+ routes into balanced operational zones for distributed training. The project's current Star Schema doesn't use spatial clustering for model partitioning.

Implementation: Apply 3-stage algorithm (coarse H3 → topology-aware subdivision → rebalancing) at H3 resolution 7 for Bengaluru.

🔍 6. SHAP Feature Importance & Progressive Ablation

Why: Provides interpretability for the ML predictions and identifies which feature families (spatial, temporal, weather, traffic) contribute most to delay prediction accuracy.

Implementation: shap.TreeExplainer for XGBoost, shap.DeepExplainer for LSTM. Aggregate by feature group.

11.4 Priority 4: Optional Research Extensions

  • xLSTM (Extended LSTM): Only if LSTM performance needs improvement. Matrix memory adds complexity but marginal gains (R² = 0.623 vs 0.6621).
  • PatchTST / Autoformer: Not recommended for this project. Both underperformed LSTM while requiring 60–80× more parameters and 2–3× more training time. The reference paper's evidence strongly discourages transformer models for short-term transit delay patterns.
  • Multi-Level Error Cancellation Analysis: Compute separate RMSE at elementary, segment, and trip levels to demonstrate that aggregation improves predictions.
